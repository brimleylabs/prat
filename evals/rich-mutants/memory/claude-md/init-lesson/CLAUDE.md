# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Rich: a Python library (>=3.10) for rich text, tables, progress bars, syntax highlighting, markdown, tracebacks, etc. in the terminal. The package is `rich/`, tests are in `tests/`. Dependencies are managed with `uv` (`uv sync`; `.python-version` pins 3.15). Runtime deps are only `markdown-it-py` and `pygments`.

## Commands

```
make test                 # pytest with coverage (TERM=unknown uv run pytest --cov=rich tests/ -vv)
make test-no-cov
uv run pytest tests/test_table.py::test_name -vv   # single test
make format               # black (format-check to verify only)
make typecheck            # mypy strict on the rich package
python tools/check_changelog.py   # changelog gate (see below)
```

Without uv: `python -m pytest -q -p no:cacheprovider tests` (~1,000 tests, a few seconds). Set `TERM=unknown` as the Makefile does, since output depends on terminal detection. Pre-commit also runs isort (black profile) and pycln.

## Conventions

- **Changelog is mandatory**: every change under `rich/` needs a new bullet under `## Unreleased` in `CHANGELOG.md` (Keep a Changelog format). `tools/check_changelog.py` compares against the merge-base with `main`, and the `.prat/project.toml` verify gates are the test run plus this check.
- mypy runs in `strict` mode with extra error codes (`ignore-without-code`, `redundant-expr`, `truthy-bool`); `# type: ignore` needs an error code.
- Document new code with docstrings; avoid abbreviations in names.
- AI-generated PRs must follow `AI_POLICY.md`: fill in the PR template, state that the PR is AI generated and name the agent, and link an issue or discussion where a maintainer approved the solution.
- Docs are Sphinx (`docs/`, `make docs`). The many `README.*.md` files are translations of the English README.

## Architecture

Everything renders through `Console` (`rich/console.py`), which is the central hub. Understanding the render protocol requires reading `console.py`, `protocol.py`, `segment.py`, and `measure.py` together:

- **Renderables** implement `__rich_console__(console, options) -> RenderResult`, yielding other renderables, `str`s (interpreted as markup), or `Segment`s. A `__rich__` method may instead return another renderable. `Console.render()` recursively flattens these into a stream of `Segment`s (text + `Style` + optional control codes). `Console` is also what turns segments into ANSI, handling color-system downgrading, legacy Windows, Jupyter, and file/export targets.
- **Measurement**: renderables optionally implement `__rich_measure__(console, options) -> Measurement` (min/max width), used by `Table`, `Columns`, `Panel` etc. to lay out within `ConsoleOptions` (width, height, justify, no_wrap, etc.).
- **Text and style layer**: `Text` (spans over a plain string), `Style`, `Color`, `Theme`/`default_styles.py` (named styles such as `"repr.number"`), `markup.py` (BBCode-like `[bold]` parsing), `highlighter.py`, and `cells.py` (character cell width, backed by `_unicode_data/`, generated by `tools/make_width_tables.py`).
- **Higher-level renderables** built on the above: `Table`, `Panel`, `Tree`, `Layout`, `Columns`, `Markdown`, `Syntax`, `Traceback`, `Pretty`, `Progress`, `Live`/`Status`, `Prompt`, and `RichHandler` (`logging.py`).
- **Live display** (`live.py`, `live_render.py`, `progress.py`, `status.py`) works by re-rendering and cursor-controlling via `Control` segments; `file_proxy.py` redirects stdout/stderr during live displays.
- `rich/__init__.py` exposes the global console and `print`/`inspect`/`pretty` helpers (the global console is lazily created). `python -m rich` runs the demo (`__main__.py`).
- Files prefixed with `_` are private internals (emoji tables, spinners, palettes, Windows console support, etc.).

## Testing notes

Tests render via `tests/render.py` (`render()` makes a fixed-width-100, truecolor, `StringIO` Console and normalizes hyperlink ids) or construct a `Console(file=io.StringIO(), width=..., color_system=..., legacy_windows=False)` and assert on the exact ANSI output. Pass explicit width and color system rather than relying on environment detection.
