check_changelog.py takes the '- ' bullets under the '## Unreleased' heading (matched case-insensitively; they may sit under '### Added/Changed/Fixed', and any other '## ' heading ends the section) and requires at least one whose exact text is not in CHANGELOG.md at the git merge-base with main (or an optional BASE_CHANGELOG path argument). Matching is by exact text, so rewording an old bullet technically counts as new, but add a genuinely new bullet in Keep a Changelog style instead. The check passes with 'nothing to describe' if nothing under rich/ changed; run it from the repo root, since it reads CHANGELOG.md by relative path.
