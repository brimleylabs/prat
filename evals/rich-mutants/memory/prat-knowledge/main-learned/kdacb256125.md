`make_progress` and `test_columns` inject `get_time` (an incrementing `fake_time` or `MockClock`) and set `auto_refresh=False`, so no real refresh thread timing is involved in the tests. Elapsed and remaining times such as `0:00:07` are baked into expected strings, so adding or removing a `get_time()` call, an extra refresh, or any change to refresh logic in rich/progress.py or rich/live.py (Progress drives a background Live refresh thread with a shared RLock) changes those values. `test_progress_max_refresh` checks that `column.max_refresh` throttles redraws.
