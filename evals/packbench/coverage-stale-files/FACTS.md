## Schema slice

All SQL lives in `coverage/sqldata.py`, in the `SCHEMA` string (lines 60 to 121). No ORM.
- `coverage_schema(version integer)`: one row, the schema version (`SCHEMA_VERSION = 7`, line 49).
- `meta(key text unique, value text)`: keys `has_arcs`, `version`, `sys_argv`, `when`, `hash`.
- `file(id integer primary key, path text unique)`: one row per measured file.
  `context(id integer primary key, context text unique)`: one row per context.
- `line_bits(file_id, context_id, numbits blob, unique(file_id, context_id))`: FK to `file` and `context`.
- `arc(file_id, context_id, fromno, tono, unique(...))`: FK to `file` and `context`.
- `tracer(file_id integer primary key, tracer text, foreign key (file_id) references file (id))`:
  one optional row per file. This is the shape a per-file fingerprint table needs.
- `CoverageData._file_map` (dict path to file id) mirrors `file`; it is filled in `_read_db`
  (line 368) and by `_file_id(filename, add=True)` (line 486). `measured_files()` (line 1039)
  returns `set(self._file_map)` without touching the database.

## How schema changes are made in this project

- There are no migrations. A new data file gets `SCHEMA` via `_init_db` (line 372, `db.executescript(SCHEMA)`).
- An existing file is checked in `_read_db` (line 338): if `coverage_schema.version != SCHEMA_VERSION`
  it raises `DataError("Couldn't use data file ...: wrong schema: X instead of 7")` (line 357).
- The comment at line 46 says to increment `SCHEMA_VERSION` on any schema change. Doing that makes
  every existing data file unreadable, which the ticket forbids. The working approach: leave the
  version at 7, add the table with `CREATE TABLE IF NOT EXISTS` for writable files (in `_init_db`
  and after the version check in `_read_db`), and tolerate its absence in read-only files.
- `doc/dbschema.rst` repeats the schema (generated by cog, `make cogdoc`); no test in the gate checks it.
  Changelog entries are fragment files in `news/*.rst` (scriv), not edits to `CHANGES.rst`.

## Traps

- Incrementing `SCHEMA_VERSION` breaks every existing data file (see above).
- In `update()`, `other_db` is attached read-only and may be an old file with no fingerprint table:
  check `other_db.sqlite_master` before selecting from it. A `read_only=True` `CoverageData` cannot
  be given the table either, so `file_fingerprint` must cope with it missing.
- `add_file_tracers` raises on a different value and adds unknown files as measured, and `update()`
  raises on conflicting tracers; the ticket wants the opposite for fingerprints on all three points
  (replace; `DataError` for unmeasured files; the merged-in value wins).
- The fingerprint is of the raw bytes. `coverage.python.read_python_source` (line 33) and
  `get_python_source` replace CRLF with LF, so hashing their result gives a different digest.
- Hash the file under its raw name (the `snapshots` key) but store it under `cached_mapped_file(name)`.
  A measured file can be gone by the time data is saved; that must not raise.
- A fresh `CoverageData(path)` on an existing file erases it on the first write unless `read()` is called first.
  It keeps the SQLite file open until `close()`, which matters on Windows when deleting it.
- `self.command_line(args)` splits with `shlex`, which eats backslashes in Windows paths.
  The gate runs a fixed list of four test files; a new test module is not part of it unless named.
- The bare `coverage` command (and `self.run_command("coverage ...")`) can be another release
  installed on PATH, not this checkout. Use `python -m coverage` from the repository root or with
  `PYTHONPATH` set.
- `HELP_TOPICS["help"]` (line 1128) is a hand-written command list; `COMMANDS` alone does not feed `coverage help`.
